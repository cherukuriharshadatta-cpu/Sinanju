# INC-2023-0418 — Duplicate charge after confirmation timeout

## What happened

A payment provider accepted and durably recorded a charge, but the client did
not receive the response before its timeout. The confirmation code retried the
same logical payment using a new request identity. The provider therefore
created a second durable charge for the same order.

For ORDER-42, the reproduced symptom is:

- one logical order
- response timeout after the first durable provider charge
- automatic retry
- **two durable charges**

## Decision

Disable automatic confirmation retries until one stable idempotency identity is
persisted and reused across every retry attempt.

## Important scope

This incident establishes why the retry guard was added. It does not prove that
retries will remain unsafe forever. If the request-identity behavior changes,
the decision should be revalidated rather than blindly preserved or removed.
